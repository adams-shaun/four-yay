# Layout Profiles and Board Visuals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build sub-projects 2 and 3 of the table UI rework (lane B, slug `ui-layout`):

- **Layout profiles**: a named library at `gorge.layouts.v1` that absorbs `layoutsettings.ts`, with presets, a Layout drawer, file export/import and keymap actions.
- **One arrangement function** for 2–8 seats (Columns, Grid, Focus; Mirrored or Same-as-mine), replacing `seatCorner`, Board's `CELL`, Quadrant's `OUTER`/`FACING` and IdentityBar's `CORNER`.
- **Sizing rules** that replace per-zone scale: card height from the rows box, the fullest-row cap, one shared opponent size, art tiles below a threshold, and overflow by overlap, scroll or wrap.
- **Board visuals**: the viewer's seat box, opponent header bars, verdigris/ember seat glows, the centre strip (turn label, phase track with dotted stops, flow and layout pills, splitter), one gilt action button, and arrows limited to the pending decision, the hovered stack item and declared combat.

**Architecture:**

- Pure modules hold every rule so they are unit-tested without a DOM:
  - `lib/layoutprofile.ts`: the `LayoutProfile` type, defaults, presets, `validate`, and the legacy-blob migration.
  - `lib/layoutlibrary.ts`: the persisted library (working copy + named profiles + order + active name), load/save, save/apply/delete/rename, the 1–9 and next/prev cycle.
  - `lib/tablearrange.ts`: `arrangeTable(players, viewer, profile, focus)`, the single seat-placement function.
  - `lib/boardregions.ts`: `regionRows(battlefield, profile)`: grouping, ordering (entry/name/power, ties by entry), stacking on/off.
  - `lib/cardsizing.ts`: `tableGeometry(...)`: the split into opponent/strip/own/hand heights, per-seat card size, the shared opponent size, art-tile and piles-column flags, and `rowFit(...)` for overlap/scroll/wrap.
  - `lib/passlabel.ts`, `lib/seatglow.ts`: what the action button says; which seat glows and why.
  - `lib/hovered.svelte.ts`: the object and seat under the pointer (zoom card, grave/exile hotkeys, hovered-stack arrows).
- A reactive shell `lib/layouts.svelte.ts` (`layoutStore`) is the only thing components read. It replaces `lib/layoutsettings.svelte.ts`.
- Components stay small and new UI goes in new files:
  - `Board.svelte` (arrangement grid), `Quadrant.svelte` (one seat's regions), `SeatHeader.svelte`, `SeatBox.svelte`, `Avatar.svelte`, `ZonePiles.svelte`, `CentreStrip.svelte`, `ActionCluster.svelte`, `LayoutDrawer.svelte`, `ZoomCard.svelte`, `ViewHotkeys.svelte`.
  - `BoardStage.svelte` composes them into the board grid; `Table.svelte` changes only its mount points and the rail/log placement.
- The prompt dock mount point: an empty `[data-prompt-dock]` container at the top of the rail, plus `layoutStore.prompt` (`placement: 'dock' | 'float'`, `float: {x, y}`) for lane C to read. The ACTIONS surface stays where it is until lane C moves it.

**Tech Stack:** Svelte 5 (runes), TypeScript 6, Vitest 5 with Playwright-backed browser fixtures.

**Spec:** `docs/superpowers/specs/2026-09-28-client-table-ui-rework-design.md`, sections "Visual language", "2. Layout profiles" and "3. Board and entity visuals".

## Rulings (where the spec is silent)

- Ruling: **library shape** is `{version: 1, current, profiles, order, active}` — `current` is the working copy every edit writes (so a drag of the splitter persists), `profiles` the named saves. The pill names `active` when `current` equals it, else the matching preset's label, else "Custom". — Same model the flow profiles use (a live blob plus named saves), so a player learns one pattern.
- Ruling: **migration** maps the legacy blob's `align.{creatures,others,lands}` onto the region anchors (left→start, center→centre, right→end), `handPeek` onto `hand` (`hover` → 50% visible and raise on hover, `always` → 100%, `never` → 50% and no raise). Per-zone `scale`, the command/hand align and `steppersOnBoard` are dropped. — The spec says sizing rules replace per-zone scale; the on-board steppers edited only that scale.
- Ruling: **the command zone stays at the front of the creatures region**, not in the piles column. — Two shipped player asks (CZ2, fb-20260917T232202Z) put it there, and a castable commander must never be hidden when the piles column collapses.
- Ruling: **entry order** is the wire's battlefield list order (the engine appends on entry); object id breaks ties. — The wire has no timestamp.
- Ruling: **log visibility** in a profile is `remember | show | hide`; `remember` (default) is today's per-table memory (seat hidden, spectator shown). The log moves from the full-width footer into the rail beneath the stack, as in the v3 mockup.
- Ruling: **"Until my turn"** arms the existing hard skip, offered only on an opponent's turn; with more than two seats it is labelled "Skip their turn", because it ends with that turn. — No until-my-turn run exists, and adding one is decision-flow work in `seatpanel.svelte.ts`, which must not grow.
- Ruling: **splitter reset** (double-click) returns `split` to the default for the seat count: 2 → 0.40, 3–4 → 0.46, 5–6 → 0.52, 7–8 → 0.50 (the mockup presets).
- Ruling: **focus** defaults to the first opponent in turn order and is not saved in the profile. — Which opponent matters changes every game.
- Ruling: **art tiles** are a CSS crop of the normal card image (the art box) with a name strip; the tile keeps the card's slot size so the sizing maths is unchanged. Default threshold 58px card width.
- Ruling: **wrap** puts a full region on two lines at half height inside its row; if two half-height lines still do not fit, the region overlaps at full height. **Overlap** never shows less than 22% of a card; beyond that the region scrolls.
- Ruling: **default bindings** for the new keymap actions: toggle log `L`, toggle stacking `S`, zoom card `Z`, open graveyard `G`, open exile `X`, next/prev layout `Ctrl+Shift+.` / `Ctrl+Shift+,`. Layout 1–9 are unbound by default (Ctrl+Shift+digit is flow profile 1–9).
- Ruling: **the hand** is sized from the same row unit as the viewer's rows: card height = row unit × 1.1, visible fraction from the profile (default 72%), rising on hover unless the profile says not to.
- Ruling: **spectators** see seat 0 (or the lowest seat) as "their" board with its seat box, no hand row and no action button.
- Ruling: **the mulligan round** keeps today's opening-hand board (strip at the top, no hand row).
